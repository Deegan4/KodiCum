v1.2.0 (2026-09-24)
- Added: Continue Watching -- a root-menu entry (and a
  ?action=widget&type=continue skin widget) listing videos you started but
  have not finished, built from existing watch history + resume points.
  No new storage: it's the intersection of the two.
- Added: Auto-play next (opt-in "autoplay_next" setting, off by default).
  When a video played from a category listing finishes naturally, the next
  item in that category (or the first item of the next page) plays
  automatically, with a short notification naming it.
- Added: "Sort by..." on category listings (Title / Rating / Release date /
  Duration), plus native Kodi duration sorting alongside the existing
  title/date/rating sort methods.
- Added: "Minimum rating" setting (Browsing category, 0-10, default 0) that
  hides videos below the threshold in categories, search results and the
  "category" skin widget.
v1.1.6 (2026-09-23)
- Fixed: the Settings -> Base API URL field was silently disconnected
  from ContentSource, which only ever read the (always-empty-by-default)
  multi-source manager's active URL. Typing a URL into that setting had
  no effect on any request.
- Fixed: the "Switch source" root menu item crashed (UnboundLocalError)
  on every use due to a variable shadowing the `sources` module.
- Added: a "static (no server)" content source mode (base_url_static
  setting / static flag on a named source). Requests become fixed file
  paths -- {base}/categories.json, {base}/list/{category}/{page}.json,
  {base}/resolve/{id}.json -- so a plain static file host with no
  server-side logic (GitHub Pages, S3, ...) can serve content; search is
  unavailable in this mode. tools/build_static_demo.py bakes the existing
  mock_server.py demo catalogue into this layout, published at
  https://deegan4.github.io/KodiCum/demo-content/ for a zero-setup,
  zero-cost way to try the add-on.
v1.1.5 (2026-09-16)

v1.1.4 (2026-09-16)

  "preview" URL (a still or animated frame). When

  image so the video is identifiable at a glance; "thumb"

  the version bumps to keep published zip bytes immutable per version

v1.1.0 (2026-08-04)
- Casting: "Play on device..." on any item sends it to a discovered TV via
  UPnP AVTransport, with DIDL-Lite metadata so the title, artwork and duration
  show on screen
- Playback controls (pause / resume / stop) from a device's context menu,
  since playback runs on the TV and outlives the add-on
- Progressive streams are preferred for casting; the add-on asks first when a
  source only offers an adaptive manifest, which most TVs cannot play directly
- Streams the TV could not fetch itself (plugin://, file://, local paths) are
  rejected up front, and UPnP error codes from a refusing device are surfaced
- Device discovery: find DLNA/UPnP MediaRenderers (smart TVs, AV receivers,
  streaming sticks) on the local network via an SSDP M-SEARCH, listed with
  their manufacturer, model and IP address
- Only devices exposing an AVTransport service are listed, so media servers,
  printers and routers are filtered out
- Scan results are cached for a configurable few minutes, with a "Scan again"
  item and a "Scan for devices now" settings button
- New settings: enable/disable discovery, discovery timeout, result lifetime

v1.0.2 (2026-07-21)
- Adaptive streaming: HLS/DASH/SmoothStreaming via InputStream Adapter, with
  optional Widevine/PlayReady DRM (license_type/license_key from /resolve)
- Quality selection: choose Ask / Best / a preferred resolution when the
  source returns multiple streams (new "streams" resolve shape)
- Response caching with a configurable TTL for categories and listings
- Automatic retry-with-backoff on transient network errors
- Skin widget endpoints (?action=widget&type=favorites|history|category)
- "Test connection" settings button and a "Clear content cache" action
